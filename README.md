# 一站式科研终端（经管版）（SciTerminal）

一站式科研终端（经管版）是一款面向科研人员的本地桌面应用，覆盖文献收集、AI 解析、PDF 精读、分类管理、灵感孵化、模拟审稿、Markdown 写作与项目管理等常见研究流程。

应用提供「实证类文库」和「模型类文库」两套文献结构。用户可以导入 PDF，由大模型提取结构化信息，在阅读器中翻译、标注和记录笔记，也可以把研究过程中产生的想法保存为灵感卡片，再通过大模型孵化为可检验、可执行的初步创新点。

> 当前源码版本：`v1.16.4`（修正思维导图 Ctrl+滚轮的缩放方向，并修掉「复制译文粘贴成一坨 JSON」）
>
> 运行方式：Windows 桌面应用，或 Node.js + 浏览器
>
> 数据存储：本地 JSON 文件和本地 PDF，不依赖云端数据库

## 下载安装

Windows 用户无需安装 Node.js，可直接下载安装程序：

- [下载最新正式版本](https://github.com/zhaojiayuan19981123/zotero-lit-tool/releases/latest)

> 注意：仓库源码可能先于 Releases 中的安装包。请以 Release 页面列出的功能与附件为准；仅推送源码不会自动替换已有安装包。

安装步骤：

1. 下载并运行 Windows x64 安装程序。
2. 按安装向导选择安装目录。
3. 安装完成后，从桌面快捷方式或开始菜单启动「一站式科研终端（经管版）」。
4. 首次启动后，进入「AI 设置」添加模型并填写自己的 API Key。
5. 如需期刊等级，在同一设置页面填写 EasyScholar SecretKey。

当前安装包未进行商业代码签名。如果 Windows SmartScreen 显示保护提示，请确认文件来自本仓库的 Releases 页面，然后选择「更多信息」和「仍要运行」。

### 应用内更新

安装后的 Windows 桌面版会在**后台自动检查新版本**：启动后查一次，之后每 6 小时再查一次。发现有更新时会主动提醒，**同一个版本只提醒一次**：

- 应用**在前台**：右上角浮出提醒卡片，可「查看更新」或「以后再说」；
- 应用**在后台**（最小化 / 隐藏）：发一条**系统通知**，点通知把窗口叫到前台；
- 提醒过就把版本号记进应用配置（`app-config.json`），重启或再次检查都不会重复弹；出现更高的新版本才会再提醒一次；
- 左侧栏底部的「检查更新」在有新版本时显示「新版本」徽标，卡片关掉后升级入口依然在。

也可以随时手动点左侧栏底部的「检查更新」。应用会读取本仓库最新的正式 GitHub Release，并按以下流程更新：

1. 点击「检查更新」比较当前版本与最新正式版本。
2. 发现新版本后点击「下载更新」，下载进度会在应用内显示；关闭弹窗不会中断下载。
3. 下载完成后保存正在编辑的内容，点击「退出并安装」。
4. 应用退出并启动 NSIS 安装程序。由于当前安装包允许用户选择安装目录，Windows 或安装向导仍可能要求确认，不能承诺完全静默安装。

浏览器开发模式没有替换桌面程序的权限，因此只会提示该功能需要安装后的桌面版。检查失败时，可在弹窗中重试，并检查网络、代理、防火墙以及 GitHub 是否可访问。

| AI 助手 | 多会话问答，可结合已导入的文献和知识内容辅助研究；回答以流式 Markdown 展示，失败后可重试 |

## 首次使用

首次启动会出现新版引导，先完成模型 API 配置，再按需填写 EasyScholar SecretKey。引导中的「添加模型」会直接打开模型编辑区；完成后可随时在「AI 设置」继续修改。

建议按以下顺序完成初始化：

1. 打开右上角「AI 设置」。
2. 添加至少一个大模型配置，测试连接后保存。
3. 将该模型设为当前使用模型，并确认「AI 总开关」已开启。
4. 如需解析图片或扫描内容，再配置一个支持图像输入的模型。
5. 如需期刊等级，填写 EasyScholar SecretKey。
6. 根据需要设置翻译服务和数据保存目录。
7. 选择「实证类文库」或「模型类文库」，导入 PDF 开始解析。

未配置大模型时，程序仍可通过内置规则提取部分基础信息，但研究背景、方法、结论和创新点等深层字段的质量会明显受限。

## 大模型配置

### 1. 配置项说明

程序支持保存最多 20 个模型配置，并可在顶部工具栏快速切换当前模型。每个配置包含：

| 配置项 | 说明 |
| --- | --- |
| 提供方 | 选择预置厂商，或选择自定义/本地服务 |
| 显示名称 | 可选，用于区分同一厂商下的多个账号或模型 |
| Base URL | OpenAI 兼容接口的版本根地址，通常以 `/v1` 结尾 |
| API Key | 模型服务商提供的密钥，仅保存在本机设置文件中 |
| 模型名称 | 接口实际接受的 model 标识，必须与服务商控制台一致 |
| 图像能力 | 自动判断、支持图片或不支持图片 |

当前模型会用于：

- PDF 文献结构化解析
- AI 助手
- 单篇论文对话
- 灵感孵化
- 模拟审稿
- 选择大模型翻译服务时的文本翻译

### 2. 添加模型

1. 打开「AI 设置」。
2. 在模型配置区域点击「添加模型」。
3. 选择服务商。
4. 检查自动填写的 Base URL，必要时按服务商文档修改。
5. 填写 API Key。
6. 选择或手动输入模型名称。
7. 设置图像能力。已收录的常见模型可保持「自动」。
8. 点击「测试连接」。
9. 测试通过后保存模型，并将其设为当前使用模型。
10. 开启「AI 总开关」，最后保存设置。

连接测试会向模型发送一个很小的 `ping` 请求，并将最大输出限制为 4 tokens，因此只会产生极少量调用消耗。测试成功仅表示接口、密钥和模型名称可以完成一次基础请求，不代表账号一定拥有充足余额或所有功能权限。

编辑已有配置时，程序不会重新显示已保存的 API Key。API Key 输入框留空表示保留原密钥；只有填写新值时才会覆盖。

### 3. Base URL 填写规则

Base URL 应填写到 API 版本根路径，程序会自动追加 `/chat/completions`。

正确示例：

```text
https://api.siliconflow.cn/v1
https://api.deepseek.com/v1
https://dashscope.aliyuncs.com/compatible-mode/v1
```

错误示例：

```text
https://api.example.com/v1/chat/completions
```

选择「自定义/本地」时，目标服务需要提供与 OpenAI Chat Completions 兼容的接口。若反向代理使用了额外路径，应填写该代理的版本根地址，而不是完整的请求端点。

### 4. 内置服务商地址

### 5. 模型名称示例

下列名称用于说明配置格式。模型是否开放、是否支持图像、计费方式及上下文长度可能随服务商调整，请以对应平台的最新控制台和文档为准。

| 服务商 | 文本模型示例 | 视觉模型示例 |
| --- | --- | --- |
| SiliconFlow | `deepseek-ai/DeepSeek-V4-Flash`、`deepseek-ai/DeepSeek-V4`、`Qwen/Qwen3-235B-A22B-Instruct-2507` | `zai-org/GLM-4.5V`、`Qwen/Qwen3.8-27B`、`Qwen/Qwen3.6-35B-A3B` |
| DeepSeek 官方 | `deepseek-chat`、`deepseek-reasoner` | 请查看官方当前支持情况 |
| 阿里云百炼 / 通义千问 | `qwen-plus`、`qwen-max` | `qwen-vl-max`、`qwen-vl-plus` |
| 智谱 AI | `glm-4-plus`、`glm-4-flash` | `glm-4v-plus` |
| OpenAI | `gpt-4o-mini`、`gpt-4o`、`gpt-4.1-mini` | 以对应模型的官方能力说明为准 |

模型名称必须完全匹配服务商接口使用的标识。网页产品名称、套餐名称和 API 模型名称不一定相同。

### 6. 两阶段图像理解

文献中的图表、公式截图或扫描页面需要视觉模型理解。程序根据配置自动选择以下流程：

- 当前模型支持图片：图片直接发送给当前模型处理。
- 当前模型仅支持文本：先由视觉模型生成客观的图片描述，再把描述交给当前文本模型继续分析。

配置方法：

1. 添加一个主要文本模型，例如 `deepseek-chat`。
2. 再添加一个支持图像输入的模型，例如 GLM 或 Qwen 的视觉模型。
3. 在图像理解设置中选择该视觉模型。
4. 分别测试两个模型的连接并保存。

如果视觉模型留空，后端会从已保存配置中自动选择一个同时具备有效 API Key 且被识别为支持图片的模型。自定义模型或刚发布的新模型可能不在内置识别列表中，此时可将「图像能力」手动设为「支持图片」。视觉模型单次请求的等待上限为 60 秒。

一个常见组合是：

```text
当前文本模型：DeepSeek 文本模型
视觉辅助模型：GLM-4.5V 或 Qwen 视觉模型
```

两个配置都必须有可用的 API Key。不同厂商的模型可以组合使用。

### 7. 常见模型问题

**测试连接返回 401 或 403**

- 检查 API Key 是否完整，是否误填了网页账号密码。
- 检查账号是否已开通对应模型的 API 权限。
- 检查模型是否属于当前 Base URL 对应的平台。

**返回 404**

- 不要在 Base URL 后重复填写 `/chat/completions`。
- 检查模型名称是否拼写正确、是否已下线或仅对特定区域开放。

**返回 429**

- 账号余额、并发限制或调用频率可能已达到上限。
- 等待片刻后重试，或在服务商控制台查看配额。

**测试成功但解析失败**

- 长文解析消耗和耗时高于连接测试，请检查余额与上下文长度。
- 文档可能是扫描 PDF，需要额外配置视觉模型。
- 切换模型后，确认顶部当前模型与设置中的启用状态一致。

## EasyScholar 配置

EasyScholar 用于根据期刊名称查询期刊等级。程序调用其开放接口，并只保留下列四类结果：

- 中科院分区
- 新锐分区
- ABS
- SSCI

### 1. 获取 SecretKey

1. 访问 [EasyScholar 官网](https://www.easyscholar.cc/)。
2. 登录 EasyScholar 账号。
3. 在账号或开放接口相关页面获取自己的 SecretKey。
4. 妥善保管该密钥，不要提交到公开仓库或发送给他人。

EasyScholar 的页面位置和使用政策可能调整，请以其官网当前说明为准。本项目使用的开放接口为：

```text
https://www.easyscholar.cc/open/getPublicationRank
```

请求使用 `secretKey` 和 `publicationName` 两个参数。应用不会要求用户在内嵌网页中登录。

### 2. 在应用中配置

1. 打开「AI 设置」。
2. 找到「easyScholar SecretKey」。
3. 粘贴从 EasyScholar 获取的 SecretKey。
4. 保存设置。
5. 确认待查询文献的「期刊/会议」字段中已有正确名称。

保存后可通过以下方式查询：

- PDF AI 解析成功后自动查询。
- 在单条文献上点击更新期刊等级。
- 使用「更新等级」批量查询。
- 在论文管理中查询期刊等级。

### 3. 匹配与限速逻辑

查询使用文献记录当前的期刊名称。若「期刊/会议」为空，需先编辑该字段，或重新解析 PDF 后再查询。

程序按顺序执行批量请求，并把全局请求间隔控制在约 550 毫秒，以适配 EasyScholar 每秒最多 2 次请求的限制。批量更新需要一定时间，请等待当前批次完成，避免连续重复触发。

当接口请求成功，但返回结果中没有中科院、新锐、ABS 或 SSCI 四类等级时，程序会记录：

```text
未收录于中科院/新锐/ABS/SSCI 分区
```

这不等同于期刊不存在，只表示本应用保留的四类体系中没有匹配结果。

### 4. EasyScholar 故障排查

**提示未配置 SecretKey**

- 返回设置页面重新填写并保存。
- 检查是否切换过数据目录，设置文件会随当前数据目录变化。

**提示密钥无效或请求被拒绝**

- 在 EasyScholar 账户中确认 SecretKey 仍有效。
- 检查接口权限、账户状态和官方调用规则。

**查不到某本期刊**

- 优先填写期刊全称，避免使用内部简称或不完整名称。
- 检查中文名、英文名和标点是否与常见出版物名称一致。
- 先手动修改「期刊/会议」字段，再重新更新等级。

**批量查询部分失败**

- 等待一段时间再重试失败项，避免触发上游频率限制。
- 检查网络连接以及 EasyScholar 服务是否可用。
- 批量更新按顺序执行，文献数量较多时属于正常耗时。

## 文献导入与解析

### 实证类和模型类文库

两类文库使用不同的研究字段：

- 实证类侧重理论基础、研究方法、研究设计、构念、结论和批判性思考。
- 模型类侧重模型设定、求解方法、参数讨论及相关理论内容。

上传前先选择正确的文库类型。把文献从实证类移动到模型类或反向移动时，原分类会被清除，避免把一个文库的分类错误带入另一个文库。

### 导入流程

1. 进入目标文库。
2. 将一个或多个 PDF 拖入页面，或使用上传按钮选择文件。
3. 等待附件上传和文本提取。
4. AI 总开关开启且当前模型配置有效时，程序自动进行结构化解析。
5. 检查标题、期刊、年份、DOI 等基础字段。
6. 必要时编辑字段、重新解析或更新期刊等级。

解析结果受 PDF 文本质量影响。图片扫描件、双栏错序、受保护 PDF 或公式密集文档可能需要视觉模型或人工校正。

## 分类管理

分类按文库类型分别保存，实证类分类不会混入模型类文库。当前分类逻辑支持：

- 新建、重命名和删除分类。
- 将文献行拖到左侧分类完成归类。
- 选中多篇文献后批量移动到分类。
- 通过「未分类」查看尚未归类的文献。
- 删除分类时保留文献，只移除相应分类关系。
- 在两个文库类型之间移动文献时重置不兼容分类。

一篇文献当前归属于其对应文库下的一个分类。整理大量文献时，可先在「未分类」中筛选，再批量移动。

## 灵感孵化

「灵感孵化」用于记录研究过程中尚未成形的想法。每张灵感卡片可保存：

- 标题
- 原始灵感描述
- 研究模式（实证类、模型类或 CCF 算法类）与自定义研究领域
- 标签
- 关联项目
- 关联文献
- AI 生成的初步创新点

使用方法：

1. 在左侧进入「灵感孵化」。
2. 新建卡片，尽量具体地写下观察、矛盾、机制猜想或待解释现象。
3. 选择研究模式并填写研究领域，例如“公司金融”“动态博弈”或“图机器学习”。
4. 添加标签，并按需关联项目和已有文献。
5. 确认当前大模型可用，点击「孵化」。
6. 等待流式输出完成，检查生成的研究问题、理论机制和可执行路径。
7. 补充原始想法后可再次孵化，生成新的版本。

孵化提示词会随研究模式变化。实证类要求变量、识别假设、内生性风险和稳健性；模型类要求原语、机制、命题、均衡与比较静态；CCF 算法类要求问题定义、技术洞见、基线、消融、指标、计算预算和可复现性。所有模式都会将没有用户提供证据的判断标为“待文献验证”，不会把“应用 X 到 Y”直接断言为创新。生成结果是研究草案，不替代文献检索、理论论证、数据可得性检查和研究伦理审查。

## 模拟审稿

「模拟审稿」让大模型以匿名、建设性的审稿人角色审读一份待投稿文稿。它用于发现论证、方法、证据、表达和可复现性风险，不提供真实期刊决定，也不能替代同行评审。

### 文稿导入与配置

1. 在侧边栏进入「模拟审稿」。
2. 点击选择文稿，或将 PDF / DOCX 文件拖入导入区域。单个文件上限为 100 MB。
3. 填写审稿人领域角色，例如“因果推断与劳动经济学领域专家”或“机器学习系统领域专家”。
4. 可填写补充的自定义审稿要求；它不能覆盖系统的真实性、安全性和非虚构约束。
5. 填写目标期刊或会议名称，点击「查询等级」可将 EasyScholar 结果作为严格度上下文。
6. 点击「开始模拟审稿」，审稿意见会以 Markdown 流式显示；失败时点击「重试」。完成后可导出 MD 或 PDF。

仅支持 `.pdf` 和 `.docx`；旧版 `.doc` 文件需要先由 Word 或 LibreOffice 另存为 `.docx`。程序提取文本后会删除临时上传源文件，审稿记录只保留提取的文本、配置和审稿结果于当前本地数据目录。超过 80,000 字符的提取文本会截断，审稿意见会提示其无法判断未提供部分。

EasyScholar 的等级仅用于调节审稿严格度和投稿匹配讨论，不是实际目标期刊的官方审稿规则，也不构成录用、拒稿或编辑决定。模型不得虚构引用、实验、数据、图表、行号、作者身份、机构或期刊政策；无法从文稿判断时会写明“无法判断”。

文稿正文、目标期刊、角色设定和自定义要求会发送给当前配置的大模型服务商以完成生成。涉及未发表论文、受保密协议约束的材料、个人信息或敏感数据时，必须先确认服务商的隐私政策、数据保留政策及所在机构的合规要求。

## 研究记录

「研究记录」用于保存实验日志、实证回归过程、模型推导和会议速记，并可与项目和小论文关联。记录正文按普通文本 / Markdown 要点编辑，点击保存后才会写入本地数据目录的 `notes.json`。

### Study 与项目联动

1. 在记录编辑框填写关联项目和关联小论文；项目卡片上的「记录」数量可直接跳转到该项目的筛选结果。
2. `Study 1` 至 `Study 12` 会作为输入建议显示，但不是固定上限。可直接填写 `Study 13`、`Pilot`、`Robustness` 或其他不超过 80 个字符的标签。
3. 在项目筛选状态下新建记录时，当前项目会自动预选。删除项目不会删除关联记录，而是解除它们的项目关联。
4. 编辑已有记录时可使用「删除记录」。删除不可撤销，建议在批量操作或版本升级前先导出数据备份。

### 模板与 AI 整理

- 经管实证模板和通用实验 SOP 模板会插入到正文当前光标处，绝不会清空或覆盖已有内容；插入后可以继续自由编辑。
- 在「AI 整理零散记录」中粘贴会议速记、实验现象或待办事项，点击整理后会以流式 Markdown 显示草稿。失败时可直接重试，表格也会正常渲染。
- 生成结果不会自动写入或替换正文。检查草稿后点击「插入到记录」，它只会在开始生成时记住的光标位置插入；仍需点击「保存」才会持久化。
- 整理提示词要求模型不得虚构数据、系数、样本、文献、方法或结论。材料不完整时会标为 `[待补充]`，而不是将推测包装成事实。

AI 整理会把用户粘贴的片段、关联项目名称/简介、论文标题，以及最多 16,000 个字符的已有正文上下文发送给当前配置的模型服务商，以减少重复内容。未公开数据、受保密协议约束的材料、个人信息或敏感研究内容，应先确认服务商的数据保留政策、机构合规要求和课题组约定。

## Markdown 笔记

左侧「Markdown 笔记」是独立于「研究记录」的长文写作区。笔记自动保存到当前数据目录的 `markdown-notes.json`，并进入应用备份。

### 新建与导入

- 点击「新建」创建空白笔记。
- 点击「导入 .md」选择一个或多个 `.md` / `.markdown` 文件。
- 也可以把 Markdown 文件拖到笔记列表、编辑器、预览区或整个笔记工作区，程序会导入一次并打开新笔记。
- 导入会把文件内容复制进应用数据，不会与原文件保持双向同步。
- 在 AI 助手里，每条回答下方都有「📥 导入笔记」：既能**新建一篇笔记**（标题按刚才的提问自动生成，正文附上时间与提问），也能**追加到已有笔记**末尾。导入只会写进这里，不会改动任何文献的笔记。

### 编辑与排版

工具栏支持标题级别、粗体、斜体、高亮、对齐、字体、字号、列表、引用、链接、代码块、公式块和表格。可在「分栏」「编辑」「预览」三种模式间切换。

公式使用 KaTeX 语法：

```markdown
行内公式：$Y = \alpha + \beta X$

公式块：
$$
Y = \alpha + \beta X + \varepsilon
$$
```

表格使用 GFM Markdown：

```markdown
| 变量 | 定义 |
| --- | --- |
| Y | 被解释变量 |
```

标准 Markdown 本身不定义字体、字号、对齐和高亮。工具栏会为这些功能插入经过安全过滤的 HTML，例如 `<mark>`、`<span style="font-size: 18px">` 和 `<div align="center">`。这类内容在本应用内可以预览，但在禁用内嵌 HTML 的其他 Markdown 软件中可能不会保留相同外观。

### 导出

- Windows 桌面版：点击「导出 MD」或「导出 PDF」，通过系统另存为窗口选择位置。
- 浏览器模式：MD 使用浏览器下载；PDF 打开打印页，由系统打印对话框选择「另存为 PDF」。
- PDF 会保留常用标题、表格、代码、公式和受支持的排版样式。复杂 HTML、远程图片或目标电脑缺少的字体仍可能出现差异，正式提交前应检查导出结果。

## AI 流式回答

AI 助手、单篇论文对话、审稿意见翻译、灵感孵化和模拟审稿均以流式方式展示用户可见的自然语言回答，并通过同一 Markdown 渲染器支持标题、列表、代码、公式和表格。请求失败时界面保留失败状态并显示重试按钮；主 AI 助手重试不会重复写入用户问题。

## 主题与界面

在「个性化」中选择主题色后，应用会同步更新页面背景、工具栏、按钮、状态色和左侧侧边栏，不只改变局部控件。主题色只影响界面外观，不会修改文献、笔记或 AI 配置。为了保持正文、表格和阅读区的可读性，部分中性色仍保持稳定。

PDF 结构化字段提取仍采用完整 JSON 响应，而不是流式 Markdown。这是有意设计：字段提取需要一次性校验结构，强行流式化会增加半截 JSON 和数据损坏风险。

## 科研日历

首页科研日历可在「历法」中分别控制：

- 农历日期
- 二十四节气
- 传统节日与常见公历节日

点击「导入」可加载 `.ics` 日历文件。当前导入器读取事件的开始日期和标题，最多处理前 3000 个事件，并按“日期 + 标题”跳过重复项。跨日事件、重复规则、提醒、时区换算和参会人等高级 ICS 字段不会转换为应用任务。

内置节日仅用于日期提示，不代表中国法定放假或调休安排。每年的法定安排可能变化，应从可信官方来源获取对应年度的 ICS 文件后导入；不要把农历节日显示当作法定休假依据。

## 每日寄语

首页根据本地日期稳定选择一句面向硕博研究生活的短句，同一天保持不变。寄语不使用虚构名人署名，也不会调用外部接口。

## PDF 阅读、翻译与笔记

打开文献附件后，可在阅读器中连续浏览 PDF。选中文本后可以：

- 翻译选中内容。
- 添加高亮。
- 创建笔记。
- 在笔记列表中回到对应位置。

翻译设置提供以下选项：

| 翻译服务 | 配置要求 |
| --- | --- |
| SiliconFlow DeepSeek | 使用当前设置中保存的大模型连接信息 |
| DeepL | 单独填写 DeepL API Key |
| MyMemory 免费接口 | 无需 API Key，受公共接口配额和可用性限制 |

涉及未公开论文、审稿材料或敏感数据时，应先确认所选模型和翻译服务的隐私政策，再决定是否发送文本。

### 笔记模式（三栏精读）

点击阅读器工具栏的「📓 笔记模式」进入三栏工作区，适合「边读边译边记」：

| 栏位 | 内容 | 说明 |
| --- | --- | --- |
| 左（默认 40%） | 原文 / 全文翻译 | 分段切换原 PDF 与 Markdown 译文；在原文中选中文字即触发中栏翻译 |
| 中（默认 20%） | 划词翻译 | 自动填充选中的原文并翻译；也可手输，`Ctrl/Cmd+Enter` 翻译；「→ 加入笔记」把原文+译文送进右栏 |
| 右（默认 40%） | 笔记 | 「Markdown」与「思维导图」两个页签，是**同一份笔记的两种视图** |

两根分隔条可拖拽调整栏宽，比例会记住；窄屏下自动改为纵向堆叠。笔记编辑后自动保存（右上角显示保存状态），切换文献或退出时强制写入，退出应用不会丢失。

**Markdown 视图**支持标题、列表、表格、公式与图片，可直接在编辑器内 `Ctrl+V` 粘贴或拖入图片。**思维导图视图**的操作与快捷键对齐 XMind：

| 快捷键 | 作用 |
| --- | --- |
| `Tab` / `Insert` | 插入子主题 |
| `Enter` | 插入同级主题 |
| `Shift+Tab` | 跳到父主题 |
| `F2` 或双击 | 编辑节点文字 |
| `Delete` / `Backspace` | 删除选中节点 |
| 方向键 | 在节点间切换 |
| `Ctrl+Z` / `Ctrl+Y` | 撤销 / 重做 |
| `Ctrl+V` | 给选中节点粘贴图片 |
| 滚轮 | 上下平移画布 |
| `Ctrl+滚轮` | 缩放画布 |

节点框会**随文字长短自动贴合**：文字短的框收紧、文字长到放不下就自动换行并把框撑高，不会把标题挤在固定宽度里显示不全。

在 Markdown 里写的大纲切到思维导图会自动成树（按标题层级与列表缩进），反之导图也会回写成缩进列表。点「⤓ 导出 .xmind」产出的文件可直接用 XMind 打开继续编辑，也可导出 PNG。

### 论文 AI 对话记录

阅读器右侧「AI 对话」页签里的问答会**按文献自动保存**，退出应用或刷新页面后重新打开同一篇论文仍能看到历史记录。点右上角「🗑 清除记录」可清空**当前这篇论文**的对话（其它论文不受影响），清除前会弹确认。

对话**同时读入论文的解析全文**（即「全文翻译」产出的 Markdown 译文），所以可以直接追问论文正文里的方法与结论，而不只是标题、作者和摘要。正文还在解析时会明确提示「本次回答可能不够完整」。

## 数据目录、备份与恢复

### 默认存储位置

Windows 桌面版将用户数据放在 Electron 用户数据目录下，通常位于：

```text
%APPDATA%\SciTerminal\data
```

从旧版本升级的用户可能仍使用：

```text
%APPDATA%\zotero-lit-tool
```

实际位置以设置页面显示的数据目录为准。用户可以指定新的数据目录，例如 `D:\SciTerminalData`。切换目录时，程序会迁移 JSON 数据和已上传附件。

为防止卸载或升级误伤数据，程序不允许把数据目录设置在应用安装目录内部。

### 自动与手动备份

- 应用启动时最多每 6 小时创建一次数据快照。
- 自动保留最近 10 份备份。
- 设置页面支持立即备份、恢复备份、导出备份包和打开数据目录。
- 文献、分类、灵感、模拟审稿、项目、任务、笔记、聊天、论文和邮件等数据分别保存在本地 JSON 文件中。

API Key、EasyScholar SecretKey 等配置也保存在本地 `settings.json`。备份包可能包含这些敏感信息，应存放在可信位置，不要上传到 GitHub、网盘公开链接或共享群组。

建议在大批量导入、修改数据目录或升级版本前执行一次手动备份。

## 导出

文献列表支持：

- CSV 导出：包含结构化字段和期刊等级，并写入 BOM 以改善 Excel 中文兼容性。
- JSON 导出：适合备份、二次处理或与其他研究工具衔接。

导出文件只包含对应导出功能选择的数据。PDF 原文件和完整应用数据应通过备份功能保留。

## 常见问题

### 应用启动后没有 AI 解析

检查「AI 总开关」、当前模型、API Key、Base URL 和模型名称。先运行「测试连接」，再对失败文献执行重新解析。

### PDF 已上传但字段为空

可能是扫描件或 PDF 文本层异常。配置视觉模型后重试；若仍失败，可先人工补充期刊和标题等基础字段。

### 切换模型后仍像在使用旧模型

确认顶部工具栏显示的当前模型，并在设置中保存修改。编辑模型时，API Key 留空会保留原值。

### 期刊等级没有显示

检查 EasyScholar SecretKey 和「期刊/会议」字段。等级查询依赖期刊名称，不依赖 PDF 文件名或论文标题。

### 更换电脑后如何迁移

在旧电脑使用「导出备份包」，将备份文件转移到新电脑后使用「恢复」。迁移完成后打开数据目录核对 PDF 附件，并重新测试外部服务连接。

### 卸载会不会删除科研数据

Windows 安装配置默认不会在卸载时删除用户数据，但仍建议先导出备份。自定义数据目录也应独立备份。

## 版本发布

维护者发布新版本时应：

1. 更新 `package.json` 和 `package-lock.json` 中的版本号，必须高于已发布版本。
2. 运行 `npm test`，再运行 `npm run dist`。
3. 确认 `dist/` 中同时存在安装程序、同名 `.blockmap` 和 `latest.yml`。
4. 提交并推送源代码，在 GitHub Releases 创建与版本号一致的 tag，例如 `v1.6.0`。
5. 将安装程序、`.blockmap` 和 `latest.yml` 原名上传到同一个 Release。
6. 将 Release 设为普通正式版本并发布，不能保持 Draft，也不要标记为 Pre-release；客户端默认不接收预发布版本。
7. 从 Releases 页面实际下载一次安装包，并用旧版客户端完成一次“检查、下载、退出并安装”的跨版本验证。

只推送源码或只创建 tag 不会形成可安装更新。GitHub 仓库若改为私有，普通客户端无法安全地内置访问令牌，当前公开 Release 更新方案将不再直接可用，需要改用受控更新服务器。GitHub 限流、区域网络、代理和防火墙也可能导致检查失败。

自动更新不会改变当前数据目录。Windows 桌面版数据通常位于 `%APPDATA%\SciTerminal\data`，旧版用户也可能仍使用 `%APPDATA%\zotero-lit-tool`；实际路径以设置页面为准。安装配置不会主动删除应用数据，但发布新版本前仍应验证迁移逻辑，并建议用户先导出备份。

当前安装程序没有商业代码签名，因此新版本仍可能触发 SmartScreen。面向广泛用户发布时，应使用受信任的 Windows 代码签名证书，并在持续集成或隔离的签名环境中保护私钥。

仓库中的 `.github/workflows/release.yml` 会在推送 `v*` 标签后，分别在 GitHub 托管的 Windows 和 macOS 构建机上生成 Windows x64、macOS arm64、macOS x64 安装包，创建正式 Release，并附带 `SHA256SUMS.txt`。在没有配置 Apple 签名凭据时，工作流会明确关闭证书自动发现，产出的 macOS 包属于未签名、未公证构建。

不要将本地 `data/`、`uploads/`、`node_modules/`、API Key 或用户文献上传到 Release 或源代码仓库。

### 数据范围与边界

该功能同步的是 **Crossref 的公开元数据**，不会下载、抓取或分发受版权保护的 PDF 全文；“原文链接”跳转至 DOI 或出版社文章页。Crossref 并不保证每条记录都含作者单位或摘要，缺失字段会如实显示“数据源暂未提供”。

当前版本为本地桌面持久化实现：用户打开应用后可同步、签到、领取和查看历史文章。电脑关机或应用不运行时，本地程序不能保证持续后台抓取、跨设备同步或系统级推送；这些能力需要后续增加账号、云端数据库、定时任务与通知服务，不能误认为当前已部署。
